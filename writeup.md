# Short Write-Up: Product Description Generator

**LLM choice.** I chose Option C, a small local LLM served by Ollama (default `gemma3:1b`, configurable through an environment variable). It needs no API key or billing, so there is no secret to leak. It also keeps product data on my own machine, and it is fast enough on a laptop for short marketing copy. The Flask app sends a prompt to Ollama's local `/api/generate` endpoint, and the prompt includes the product name, keywords, selected tone and length. For the stretch goal, each tone maps to a customer segment (for example, "luxury" targets premium customers and "playful" targets younger shoppers) and to style instructions. This works as a small rule-based decision layer that programs the prompt. The app also handles errors: Ollama not running, a missing model, timeouts, empty output and blank form input each show a clear message instead of crashing.

**Challenges.** *(Edit this to match your own experience.)* Small models sometimes ignore the length instruction, repeat the keywords awkwardly, or invent specifications that weren't provided. I reduced this by rewording the prompt to say "use only the information given, do not invent specifications," and by giving an explicit word count per length option. Other challenges were handling the case where the local server isn't running and keeping the UI responsive while the model generates.

**Improvements, retail relevance and ethics.** Real retail systems go well beyond this: they generate descriptions at catalog scale from structured product data, personalize copy by customer segment or browsing behavior, run A/B tests to see which version converts, and localize into multiple languages. I could extend this app with CSV bulk upload, SEO keyword scoring, a human approval queue, and a feedback loop that records which descriptions sell best. Ethical considerations include factual accuracy (a model can "hallucinate" features, materials or certifications, which could mislead customers or create legal liability), so a human should review output before publishing. Other concerns are transparency about AI-written content, bias in tone and targeting toward customer groups, avoiding manipulative persuasion, and protecting customer and product data (a local model helps here).
